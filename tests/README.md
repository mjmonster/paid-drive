# 验收测试

在项目根目录运行：

```bash
python -m unittest discover -s tests -v
```

测试使用 Python 标准库 `unittest` 和 FastAPI 的 `TestClient`。每个测试都在临时目录创建独立的图片和 SQLite 数据库，不读取网站的实际数据库、不连接 ZPay、不发送真实邮件，也不依赖演示合集存在。支付平台查询结果使用模拟响应；恢复链接只从隔离的测试数据库读取。

## 后端自动化测试覆盖

- 前三张免费预览可以公开访问，后续原图及合集 ZIP 需要对应合集的购买权限。
- 匿名接口不提供付费原图 URL、文件路径、原始内容或内嵌图片；下载参数、Range 请求和静态路径不能绕过权限，其他浏览器不会共享买家的购买权限。
- 私有合集目录不能与公开静态目录重合或互相包含；启动检查包含符号链接解析后的路径。
- 订单及待付款操作属于创建订单的浏览器；价格由后端决定，并保存下单时的快照。
- 默认合集按配置选择；回跳订单标识只能定位当前浏览器所属的订单，本身不能解锁内容。
- 浏览器回跳参数和伪造通知不能授予访问权限；真实通知仍须与支付平台确认结果匹配，并正确处理重复通知。
- 同一支付平台交易不能重复支付另一张订单。
- 可选邮箱的绑定需要购买权限，恢复需要完成邮箱验证；临时链接会过期、仅能使用一次，且不出现在普通 API 响应中。
- 找回请求不会透露某个邮箱是否存在购买记录。
- 即使演示与真实模式共用一个数据库，演示会话、订单和邮箱凭证也不能解锁真实购买内容。
- 已售文件内容、顺序和预览范围在同一版本下保持固定；文件路径不能逃逸到私有合集目录之外。
- 拒绝跨源修改请求、格式异常的通知以及不完整的真实环境配置。

## 手机叠卡画廊的人工验收

以下是交互验收步骤，不代表这些检查已经执行通过。实际完成情况与设备／视口范围统一记录在项目根目录的 `VALIDATION.md`。

1. 使用没有购买记录的浏览器打开合集链接。主界面应是一叠可横向切换的图片卡片，页面不应展开为长图片网格或购买侧栏。
2. 左右滑动查看前三张免费图片，确认它们显示真实预览内容。继续滑动时，应显示合成剪影／模糊占位卡片及解锁入口。
3. 查看页面元素和网络请求。未解锁卡片不应加载付费原图，也不应在背景图、隐藏图片、预加载请求或前端数据中嵌入原图像素；模糊效果应作用于独立占位图形。
4. 尝试直接访问付费图片和 ZIP 地址，确认后端拒绝未购买请求。视觉上的锁定只是提示，最终访问判断应始终来自服务器。
5. 在演示模式完成一次明确标注的模拟付款。确认该合集所有卡片一次性解锁，可在同一叠卡画廊继续浏览；不要求逐张购买，其他合集保持原来的权限。
6. 检查单张图片和 ZIP 下载入口。说明应准确区分下载文件与保存到手机相册；下载按钮不能声称已经自动存入相册。
7. 检查横向滑动、正常纵向滚动、可用的按钮切换方式、客服弹层和邮箱恢复入口，确认操作不会被底部控件或卡片遮挡。对真实微信内浏览器、Safari 和 Chrome 的验证应分别记录。

占位卡片不包含付费原图像素，付费图片请求也经过后端检查；这两项共同保证未购买者不能通过简单删除 CSS 模糊效果取得原图。该方案不提供 DRM，也不承诺阻止已购买用户截图、复制或分享已经下载的图片。

## 外部集成与当前限制

自动化测试使用模拟的支付平台响应，不能证明某个实际商户账号、外部回调地址、反向代理或 SMTP 账号已经配置正确。微信内浏览器与 Safari／Chrome 的会话可能不同；切换浏览器后，需要使用已验证邮箱恢复访问，或通过微信客服核实交易后人工恢复。
